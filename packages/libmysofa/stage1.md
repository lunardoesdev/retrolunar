# libmysofa build forecast

- Recipe: `generic.lua`, source `source.lua`
- Version pinned: **1.3.5**, from the git tag `v1.3.5` of
  `github.com/hoene/libmysofa`
- Build system: **CMake** (`generic.lua`). No autotools build exists.
- Config template: `src/config.h.in`, consumed by
  `configure_file (config.h.in config.h)` at `src/CMakeLists.txt:3`. It is a
  cmake template (it interpolates `${CMAKE_INSTALL_PREFIX}` and the
  `CPACK_PACKAGE_VERSION_*` variables), so no autotools timestamp guard
  applies and none is present.
- Requires: `libmysofa@source` and **`zlib`** (`generic.lua:1-2`). zlib is in
  this repository (`packages/zlib`) and is a genuine link dependency — see
  risk 2.

## Source size — read this before bumping the version

**The release archive is 208,427,964 bytes (199 MiB) compressed and 249 MB
extracted, and 99.2% of that is test data.**

Measured, not estimated:

- archive: 208,427,964 bytes; `gzip -t` clean; 183 tar entries, 164 files
  after extraction
- `du -sh tests` → **248 MB**
- `du -sh --exclude=tests .` → **1.9 MB**

The two largest members alone are
`tests/TU-Berlin_QU_KEMAR_anechoic_radius_0.5_1_2_3_m.json.bz2` at 49,635 KB
and the matching `.sofa` at 41,049 KB — public HRTF measurement sets. Of 183
entries, **79 are under `tests/`**; the entire buildable library is 1.9 MB.

There is no smaller release: upstream publishes **no source tarball at all**.
Its GitHub releases (`v1.3.5` and earlier, plus the rolling `latest` tag
`r550@648eed0`) carry only `mysofa.lib` and `mysofa.pdb`, Windows import
libraries, ~1.7 MB and ~135 KB. So the git tag archive is the only source
that can be fetched at all, which is why `source.lua` uses it rather than a
release asset.

The recipe keeps the whole tree, including `tests/`, because `source.lua` is
fetch-only and its job is to land upstream's tree unmodified. The cost is
one 208 MB download and a 249 MB `nest/source/libmysofa/` per source
refresh, shared across all target systems. If a reviewer considers that
unacceptable, dropping `tests/` at unpack time is the single change that
removes 248 MB of it, and it cannot affect the build: `BUILD_TESTS=OFF` means
no part of `tests/` is ever read — the test registrations at
`CMakeLists.txt:48-118` are the only consumers, and they are all inside
`if(BUILD_TESTS)`. I did not make that change, because filtering upstream
content in the fetch stage is a policy call for the reviewer, not a detail I
should decide silently.

## What gets installed

- `lib/libmysofa.a` (`src/CMakeLists.txt:58`, `OUTPUT_NAME mysofa` at `:67`)
- `include/mysofa.h` (the `PUBLIC_HEADER` at `:53-55`, installed at `:73`)
- `include/mysofa_export.h` (`src/CMakeLists.txt:149`, generated by
  `generate_export_header` at `:143-144`)
- `lib/pkgconfig/libmysofa.pc` (`CMakeLists.txt:124`), from
  `libmysofa.pc.cmake`, carrying `Libs.private: -lz -lm` from
  `src/CMakeLists.txt:14-15`
- `lib/cmake/mysofa/mysofaConfig.cmake`,
  `lib/cmake/mysofa/mysofaConfigVersion.cmake`,
  `lib/cmake/mysofa/mysofaTargets.cmake` (`CMakeLists.txt:128-132`, `:156-160`)

**Data files loaded from the prefix: yes, two of them.**
`CMakeLists.txt:42-44` installs `share/default.sofa` and
`share/MIT_KEMAR_normal_pinna.sofa` into `${CMAKE_INSTALL_DATADIR}/libmysofa`,
i.e. `share/libmysofa/`. `MIT_KEMAR_normal_pinna.sofa` is a real file of
**1,173,158 bytes**. `default.sofa` is a **symlink to it** (27-byte link
target, pointing at `MIT_KEMAR_normal_pinna.sofa`), so cmake installs the
resolved content and the prefix ends up with two ~1.15 MB copies under the
same name pair. A consumer that wants a default HRTF loads
`share/libmysofa/default.sofa` from the prefix — this is the one runtime
data dependency of the three packages in this batch.

Note for anyone auditing that tree: `find share -type f` lists **only**
`MIT_KEMAR_normal_pinna.sofa`. `default.sofa` is invisible to a `-type f`
search because it is a symlink. It is present — verified by `test -f`, by
`ls -la`, and by `tar -tzf`, which lists both `share/default.sofa` and
`share/MIT_KEMAR_normal_pinna.sofa`.

## Verdicts

| system | verdict | reason |
|---|---|---|
| aarch64-android21 | WILL BUILD | C and C99 only for the shipped library: `project (libmysofa C CXX)` (`CMakeLists.txt:2`, so a C++ compiler must configure cleanly, which every system here provides), `set (CMAKE_C_STANDARD 99)` (`src/CMakeLists.txt:1`), and the `libsrc` list at `src/CMakeLists.txt:31-51`. With `-DBUILD_TESTS=OFF` the entire test tree is out: `src/tests/` is referenced only from the `if(BUILD_TESTS)` block starting at `src/CMakeLists.txt:153`, and `pthread_cancel` at `src/tests/multithread.c:147` — an API-24 gate — goes with it. A grep of the shipped sources for `nl_langinfo`, `mktime_z`, `posix_spawn`, `O_BINARY`, `mblen`, `getpass`, `process_vm_readv` and `POSIX_MADV_*` returns **no hits**. `find_library (MATH m)` at `src/CMakeLists.txt:8` succeeds: the NDK sysroot carries `libm.so` at every API level from 21 up (checked for `aarch64-linux-android/21`). Nothing is compiled or run on the host — with tests off, no executable target is defined at all. |
| aarch64-android24 | WILL BUILD | As above, and this is the level where `pthread_cancel` would have become available anyway; the flag is still required for the CUnit reason, not the pthread one. |
| aarch64-android35 | WILL BUILD | As above. zlib resolves to this prefix via `$CMAKE_PREFIX_PATH` before the NDK sysroot's own `libz.so`, because the toolchain file sets `CMAKE_FIND_ROOT_PATH` to `$PREFIX;$SYSROOT` in that order and `CMAKE_FIND_ROOT_PATH_MODE_LIBRARY ONLY`. |
| x86_64-android35 | WILL BUILD | As above. No CPU-dependent source selection exists in `libsrc`; the resampler (`src/resampler/speex_resampler.c`) is plain C with runtime dispatch, so no row is architecture-blocked. |
| x86_64-mingw | WILL BUILD | As above. `find_library (MATH m)` is skipped on Windows — `src/CMakeLists.txt:7-11` sets `MATH ""` under `NOT WIN32`/`WIN32` — so no libm lookup to miss. The `MSVC` branch at `src/CMakeLists.txt:16-29`, which requires a `nuget` executable and would `FATAL_ERROR` without one, is not taken: mingw is `WIN32` but not `MSVC`. **Conditional on zlib:** this needs a mingw zlib in the prefix, which `require("zlib")` provides via `packages/zlib/generic.lua`. If that has not been built for `x86_64-mingw` yet, `include (FindZLIB)` (`src/CMakeLists.txt:12`) cannot resolve it. That is a build-order fact, not a defect. |
| clang-native | WILL BUILD | As above, minus the toolchain-file argument — here zlib comes from the native prefix. |

`armv7a`/`i686` Android behave as `aarch64-android21`: the recipe contains no
`case $HOST_ARCH`, and libmysofa makes no architecture decision anywhere in
its build files.

## API level

**No new wall, given `-DBUILD_TESTS=OFF`.** The one gated call in the whole
tree is `pthread_cancel` (`src/tests/multithread.c:147`), and it is behind
that switch. Everything the shipped `libsrc` set calls is API-21-clean:
`fopen`/`fread`/`fwrite`/`fseek`, `malloc`/`free`, `memcpy`/`memset`,
`snprintf`, `pow`/`sqrt`/`cos`/`sin` (libm, already in `LDFLAGS` on Android),
`clock_gettime` via zlib's gunzip path, and pthreads are not used by the
library at all. No `mktime_z`, no `nl_langinfo`, no `iconv`.

## Risks / what a reviewer should check

1. **`-DBUILD_TESTS=OFF` is mandatory and fails at *configure* time, not
   build time.** `BUILD_TESTS` defaults ON (`CMakeLists.txt:8`) and
   `src/CMakeLists.txt:156` is `find_package (CUnit REQUIRED cunit)`.
   CUnit is absent from this prefix and from the backlog — checked, there is
   no `packages/cunit` and no `include/CUnit` in any built nest prefix. With
   the option left on, `cmake -S . -B build` aborts with a CUnit-not-found
   error before a single object file is produced. This is the flag most
   likely to be dropped by a future editor, which is why the recipe comment
   gives both reasons.
2. **zlib is a real link dependency, not optional.** `src/hdf/gunzip.c` is in
   the library source list (`src/CMakeLists.txt:37`), so `libmysofa.a` will
   carry an undefined `inflate`/`uncompress`. `include (FindZLIB)`
   (`src/CMakeLists.txt:12`) and `Libs.private: -lz -lm`
   (`src/CMakeLists.txt:14-15`, rendered by `libmysofa.pc.cmake:10`) both
   assume it. The `require("zlib")` at `generic.lua:2` is what puts it in the
   prefix. Worth noting that the NDK sysroot also ships a `libz.so` at every
   API level, so a missing zlib here would *not* fail loudly at configure
   time on Android — it would silently bind the target to the sysroot's zlib.
   `$CMAKE_PREFIX_PATH` is searched first, so the correct one wins.
3. **No autotools timestamp guard, and correctly so.** This is CMake. For the
   record, the tree's only `*.h.in` is `src/config.h.in`, and there is no
   `configure`/`aclocal.m4` at all — libmysofa is cmake-only. `src/config.h.in`
   is 8 lines and contains no `@VAR@` substitutions; it interpolates cmake
   variables directly.
4. **`project (libmysofa C CXX)` needs a working C++ compiler on every
   target**, including the two that are otherwise pure C. Every system here
   exports `CXX` and the cross systems' `$CMAKE_FLAGS` include
   `-DCMAKE_TRY_COMPILE_TARGET_TYPE=STATIC_LIBRARY`, so cmake's C++ compiler
   check links a static library rather than a runnable binary. No emulation
   is involved, but a system added later without `CXX` would fail here.
5. **The `share/libmysofa/` install is two ~1.15 MB copies of one file.**
   `CMakeLists.txt:42-44` installs both `share/default.sofa` and
   `share/MIT_KEMAR_normal_pinna.sofa`, and the first is a symlink to the
   second. cmake resolves the symlink and writes the content twice. That is
   upstream's intent — `default.sofa` is the name a consumer loads by
   default — but it doubles the package's data footprint, and a reviewer
   counting `share/libmysofa/*` will see 2 files where the tree has 1.
6. **`POSITION_INDEPENDENT_CODE` is tied to `BUILD_SHARED_LIBS`**
   (`src/CMakeLists.txt:67-68`), so with shared off the target asks cmake for
   no PIC. The Android systems already put `-fPIC` in `$CFLAGS`, so the
   archive is still position-independent there; `clang-native` and `x86_64-mingw`
   do the same. Not a defect, but it means the flag is not independently
   controlled.

## How to verify once built

- `lib/libmysofa.a`, `include/mysofa.h`, `include/mysofa_export.h`
- `lib/pkgconfig/libmysofa.pc`; `pkg-config --modversion libmysofa` → **1.3**
  (note: `PROJECT_VERSION` is built from major.minor only,
  `CMakeLists.txt:28-29`, so it reports `1.3` and not `1.3.5`)
- `llvm-objdump -f lib/libmysofa.a | head` → `elf64-littleaarch64` on aarch64
- `llvm-nm -u lib/libmysofa.a | grep -cE 'inflate|uncompress'` → **non-zero**,
  which is the expected and correct result (risk 2), and proves `gunzip.c` is
  really in the archive rather than being an unresolved mess
- `find $PREFIX/lib -name 'libmysofa.so*'` must be **empty**
- `test -f $PREFIX/share/libmysofa/default.sofa` and
  `test -f $PREFIX/share/libmysofa/MIT_KEMAR_normal_pinna.sofa` → both true;
  the files are the package's own, so this count is scoped and safe
- `find $OUT -name 'mysofa2json' -o -name 'external' -o -name 'multithread' | wc -l`
  → must be **0**, scoped to the three test executables named at
  `src/CMakeLists.txt:159`, `:166`, `:201`; this is the check that
  `-DBUILD_TESTS=OFF` really took and that CUnit was never needed
- `grep -c 'Libs.private: -lz -lm' $PREFIX/lib/pkgconfig/libmysofa.pc` → **1**,
  proving the zlib dependency was recorded for consumers
