- Recipe: `generic.lua` only, source `source.lua`
- Version pinned: 1.33.7
- Build system: autotools, **fully generated in the release tarball**.
  `configure` (702414 bytes, "Generated by GNU Autoconf 2.71 for mpg123
  1.33.7"), `aclocal.m4` (83526) and `Makefile.in` (458218) all ship real —
  verified by listing the tarball. The only config template is
  `src/config.h.in`; there is no top-level one.

  generated files ship.

## API level notes

**The API level is irrelevant to this package.** mpg123 does not reference
`nl_langinfo`, `getsubopt`, `scandir`/`versionsort`,
`program_invocation_short_name`, `get_current_dir_name`, `fread_unlocked`,
`argp_parse`, `mktime_z`, `posix_spawn`, `process_vm_readv` or `O_BINARY`.
It decodes MPEG audio with plain C plus its own assembly.

## Risks / what a reviewer should check

- **A retracted false premise, recorded because it is exactly the failure
  this project has been cleaning up all session.** An earlier version of
  this file and its recipe claimed mpg123's release tarball ships
  **zero-byte** `configure`, `aclocal.m4` and `Makefile.in`, and built a
  whole `autoreconf -fvi` + `autoconf@native` + `automake@native` remedy on
  top of it, marking five rows WILL NOT BUILD. **That was wrong**, and the
  cause is worth recording: the `ls -la` that produced those zeros was run
  against a *truncated extraction* of the tarball, so the files had never
  been written. The tarball ships real files. An autoreconf in a recipe is
  not just unnecessary, it is a hazard — it regenerates a build system that
  was correct.
- **`--disable-moderate` was also invented and did not exist**; it is not in
  mpg123's `configure.ac` at all. It is gone from the recipe.
- **The recipe bypassed `$AUTOCONF_CONFIGURE_FLAGS`**, giving its own
  `--prefix="$OUT"` and no `--host`. mpg123's `configure` *is* generated
  autoconf and does accept `--host`, so the system's flags are correct here
  and the override was a third, independent defect on the same package.
  Fixed: the recipe now uses `$AUTOCONF_CONFIGURE_FLAGS` like every other
  autotools recipe in the prefix.
- **`src/config.h.in` is the real template** and there is no top-level one —
  the guard names the right file because there is exactly one.
- **mpg123 builds host-adjacent code**: `libsyn123`/`libout123` are
  ordinary libraries here and `bin/hotplug` is a small tool. Nothing in the
  recipe runs any of it.
- **mpg123 has no generated `Makefile.in` for its tools/ or tests/ in the
  default build**, so `make` is the library and the decoder only. The
  `-lpthread` wall that stops libnl-3 does not apply: mpg123's
  configure tests for pthreads and configures accordingly, and nothing in its
  sources requires a thread library unconditionally.

## How to verify once built

Not verifiable on any cross target until the autoreconf question is settled.
On `clang-native`, if it gets that far:

- `bin/mpg123`, `bin/mpg123123`
- `lib/libmpg123.a` (or `.so` — mpg123's default is libtool's, so record
  which appears)
- `lib/pkgconfig/mpg123.pc` and `pkg-config --modversion mpg123` → `1.33.7`
- `file bin/mpg123` → host x86_64 ELF on `clang-native`; an Android ELF would
  mean the wall was wrong
- **The check that proves the autoreconf worked:** the build log shows
  `autoreconf` output, and `configure -v | grep 'configure generated by'`
  shows a real autoconf version rather than an empty file
- Never run any of it on the build host as a test — on a target prefix that
  is forbidden outright
