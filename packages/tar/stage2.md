# tar 1.35 — stage 2 review

Reviewed against AGENTS.md, the three representative systems, and the unpacked
tree at `nest/source/tar/`. I did not build.

## What the recipe gets right

- **The guard is correct.** Verified against the real tree:
  `AC_CONFIG_HEADERS([config.h])` with `config.h.in` at the top level, which is
  what `generic.lua:7` touches. (`sed` in this same shard gets the equivalent
  wrong — its template is `config_h.in` — so this is worth stating rather than
  leaving implicit.)
- `./configure $AUTOCONF_CONFIGURE_FLAGS` with no switches of its own. tar is a
  single self-contained program: no optional library, no feature to choose, and
  the only knobs worth having (`--selinux`, `--libaclocal`, NLS) are all
  correctly absent because none of their dependencies are in this prefix. The
  recipe is system-neutral and nothing is hardcoded to a target.
- `require("tar@source")` names no missing package.
- `make` and `make install` are bare. **Not a defect** — bare `make` is serial
  by default, which I verified empirically (`MAKEFLAGS` is empty without `-j`).
  Adder A's finding #7 is correct on this and I am explicitly not failing the
  package for it.

## What the forecast should add

tar installs a man page and an info file that are **build products, not shipped
files** in the usual GNU arrangement:

- `share/man/man1/tar.1` is regenerated by `help2man` from the freshly built
  binary unless it is disabled. If the build host has `help2man`, fine; if not,
  `make` can stop. The recipe passes no `--disable-man` equivalent because tar
  has no such option, so the safeguard, if any, is the shipped `.1`'s mtime.
- `info/tar.info` likewise may be regenerated with `makeinfo`.

Neither is a defect in the recipe, but both are the class of thing that turns
into a red build on a host missing a tool, and the builder should be told to
watch for a `help2man`/`makeinfo` invocation in the log rather than being
surprised by one. This is the same hazard `diffutils` handles with an explicit
`touch man/*.1` and `texinfo` avoids with `--disable-asciidoc`; tar has neither
lever, so the honest statement is "check the log".

## Carried to the build

- `bin/tar` — `llvm-objdump -f bin/tar | head -3` → `elf64-littleaarch64` (Android) / `pei-x86-64` (mingw), and `llvm-objdump -p` should name the Android API level.
- `bin/gtar` — `[ -e bin/gtar ]`; tar installs the unversioned name plus a versioned link, and some consumers' build systems look for `gtar`.
- `share/man/man1/tar.1` — `[ -s share/man/man1/tar.1 ]`. **Use `-s`, not `-f`**: a zero-byte man page is the signature of a `help2man` attempt that produced nothing.
- `info/tar.info` — `[ -s info/tar.info ]`, same reasoning for `makeinfo`.
- No library, no headers, no `.pc`; tar is one program.
- **Never run `bin/tar`.**
