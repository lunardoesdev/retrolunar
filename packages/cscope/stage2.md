# cscope review (stage2)

Recipe: `generic.lua`. Source: `source.lua`, cscope 15.9 (Debian
`.orig.tar.xz`). Tarball verified with `tar tf` (115 entries, top dir
`cscope-15.9/`), extracted to `/home/si/.revE/src2/cscope-15.9`.

## 1. Is it using the SYSTEM?

Yes. `./configure $AUTOCONF_CONFIGURE_FLAGS`, `make -j1`, `make -j1 install`.
No hardcoded triplet/API, no `export` of search flags, no `sed`/patch, no
fan-out.

**The `@native` require spelling is correct — this was the specific thing to
check.** Both `require("flex@native")` and `require("bison@native")` are right,
and there is exact precedent in this tree: `packages/libnl-3/generic.lua:4-5`
uses the identical pair. `packages/flex` and `packages/bison` both exist, and
`bison/generic.lua:1` itself requires `gperf@native` — the same host-tool
chain, so the pattern is established rather than novel. These are generators
that must **run** on the build host, never on the target, which is exactly what
AGENTS.md's `@native` form expresses.

## 2. Is it doing what the package needs?

**The generated `configure` is real.** `head -3 configure | tail -1` →
`# Generated by GNU Autoconf 2.69 for cscope 15.9.` — so no `autoreconf`
bootstrap, and unlike cmph/minizip this package never faces that question.

**The guard is correct and the template name is real.** `configure.in:5` is
`AC_CONFIG_HEADERS([config.h:config.h.in])` — the `:` form, explicitly naming
`config.h.in` — and `find . -name '*.h.in'` returns exactly one file,
`./config.h.in`. So the touch list is right and complete. `configure.in` is
this project's spelling (not `configure.ac`), which does not change anything
the recipe does. Guard position is correct: after `./configure`.

**The flex/bison requires are more load-bearing than the recipe claims, and I
checked why.** The tarball ships pre-generated `scanner.c`, `fscanner.c` and
`egrep.c` alongside their `.l`/`.y` sources, and in the *tarball* the `.c`
files are newer:

```
2017-11-07 10:14:58  src/egrep.y     2017-11-07 10:16:24  src/egrep.c
2017-11-07 10:14:58  src/fscanner.l  2017-11-07 10:16:26  src/fscanner.c
2017-11-07 10:14:58  src/scanner.l   2018-07-25 04:30:34  src/scanner.c
```

That ordering is what keeps automake's `.l.c`/`.y.c` suffix rules
(`src/Makefile.in:938,941`) from firing. **But the recipe's first build step is
`cp -r $NESTDIR/source/cscope/* .`, and plain `cp -r` does not preserve
mtimes** — I verified this directly:

```
before cp -r:  f.c 2018-07-25 14:30:34   f.l 2017-11-07 20:14:58
after  cp -r:  f.c 2026-10-01 14:30:38.946   f.l 2026-10-01 14:30:38.945
```

Both files land at "now", and their relative order becomes a function of
directory read order rather than of upstream's intent. In my test `.c` came out
fractionally newer, but that is not guaranteed — with a different readdir
order `.l` wins, the suffix rule fires, and the build dies looking for `lex`.
So `require("flex@native")` and `require("bison@native")` are **not** merely
"required because the Makefile mentions them" — they are insurance against an
mtime race the recipe itself creates. The comment says "required because
`src/Makefile.in` regenerates … at build time", which is the right conclusion
for a slightly wrong reason; worth a sentence of correction, but the requires
must stay either way.

**The curses handling is honestly reported, not papered over.** The comment
notes that with no ncurses in this prefix, `configure.in:254-265`
(`AC_SEARCH_NCURSES`) searches only host paths, finds nothing, and
`src/Makefile.am` then links with no `$(CURSES_LIBS)`. Leaving the build to
whatever the target sysroot offers is the correct call: adding a hardcoded
`--without-curses` or a guessed `CURSES_LIBS` would be a target fact. Good.

**No host program is compiled and no target binary is run.** flex and bison are
generators that run on the build host; `cscope` itself is a target program that
is compiled and installed but never executed during the build. The GUI is not
built by this path (`src/Makefile.in` builds `cscope`, `gscope`, `cvs*`
console tools).

## API gates

The adder's claim is that cscope uses none of the API-21 walls, and I agree
with the direction: this is curses + stdio + process-spawning code from 1998,
with no `nl_langinfo`, `mktime_z`, `posix_spawn`, `process_vm_readv`,
`mblen`/`getpass` or `O_BINARY`. The real risk on Android is curses, not the
API level — which is what the forecast says.

## Forecast

I agree with **6 of 6**, including the single UNCERTAIN.

The `aarch64-android21` UNCERTAIN is the right call and is correctly reasoned:
the uncertainty is curses availability on a Bionic sysroot with no
`ncurses.pc`, not a missing symbol. UNCERTAIN is a legitimate answer per
AGENTS.md, and the row names the one thing it could not settle. Upgrading it to
WILL BUILD without a build would be the error.

The five WILL BUILD rows are consistent with a generated configure, a correct
template, `@native` generators, and no API gate.

## Artifacts — what actually installs

- `bin/cscope`, `bin/gscope`, `bin/cvs*` (console tools; no GUI)
- `share/man/man1/cscope.1` etc.
- **No library** — cscope is a program, so there is no `libcscope.a` and no
  `.pc` file. A check for either would be a false failure.

## Carried to the build

```sh
# 1. artifacts. No library and no .pc — this is a program.
test -x "$OUT/bin/cscope" || echo "MISSING bin/cscope"
test -x "$OUT/bin/gscope" || echo "MISSING bin/gscope"
find "$OUT/lib" -name 'libcscope*' | wc -l          # expected 0
ls "$OUT/lib/pkgconfig"/cscope.pc 2>/dev/null       # expected: no such file

# 2. THE GENERATOR CHECK, and this is the one that can fail. Confirm flex and
#    bison ran on the build host and were not cross-compiled.
grep -c 'flex\|lex ' "$WORK/config.log" | head -1
$OBJDUMP -f "$NATIVE_PREFIX/bin/lex" 2>/dev/null | head -3   # must be HOST machine
$OBJDUMP -f "$NATIVE_PREFIX/bin/yacc" 2>/dev/null | head -3 # must be HOST machine

# 3. and confirm no lex/yacc ran on the target: the build log must show the
#    suffix rules staying dormant
grep -E 'YLWRAP|LEXCOMPILE|YACCCOMPILE' "$WORK/src/Makefile" | head -3
grep -ciE 'ylwrap|yacc.*egrep\.c|lex.*scanner\.c' "$WORK/build.log"   # expected 0

# 4. the generated config.h must exist and be reflected
test -f "$WORK/config.h" || echo "MISSING config.h"
grep -c 'HAVE_CONFIG_H' "$WORK/config.h"           # expected 1

# 5. curses: report honestly rather than asserting either way. If has_curses is
#    false the binary links with no CURSES_LIBS, which the recipe says is
#    expected.
grep -E 'HAVE_NCURSES|HAVE_CURSES' "$WORK/config.h"

# 6. ELF machine per family — these are target programs
$OBJDUMP -f "$OUT/bin/cscope" | head -3
$OBJDUMP -f "$OUT/bin/gscope" | head -3

# 7. scope was never RUN by the build (no-emulation rule)
grep -ciE '\.\/cscope|cscope -' "$WORK/build.log"    # expected 0
```
