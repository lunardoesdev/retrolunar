# stage1 — cmph 2.0.2 (build forecast)

## Correction: the autoreconf premise was wrong, and it is retracted

An earlier draft of this file claimed the tarball ships **no** generated
`configure`, no `aclocal.m4` and zero `Makefile.in`, and marked all six
rows WILL BUILD on the strength of an `autoreconf -fi` bootstrap. **Both
halves of that were wrong**, and the recipe has been rewritten.

The wrongness was in the *source tarball*, not in the reading. That draft
fetched `cmph_2.0.2.orig.tar.gz` from the **Debian pool** (3375316 bytes,
717 entries), and that archive really does contain exactly one build-system
file, `configure.ac`. I verified that absence against the tarball index
rather than trusting an extraction, so the check was sound — it was applied
to the wrong artifact.

The **upstream release tarball** `cmph-2.0.2.tar.gz`
(`github.com/bonitao/cmph/releases/download/v2.0.2/`, 532528 bytes, 169
entries) ships the complete generated build system:

```
cmph-2.0.2/configure        604968 bytes
cmph-2.0.2/aclocal.m4        42148 bytes
cmph-2.0.2/config.h.in        2264 bytes
cmph-2.0.2/Makefile.in       28511 bytes
cmph-2.0.2/src/Makefile.in
cmph-2.0.2/examples/Makefile.in
cmph-2.0.2/cxxmph/Makefile.in
cmph-2.0.2/tests/Makefile.in
cmph-2.0.2/man/Makefile.in
```

`configure` carries `# Generated by GNU Autoconf 2.69 for cmph 2.0.2.` at
line 3 — checked with the banner, not only the size.

So **the bootstrap is not merely undesirable, it is unnecessary**, and the
recipe is now an ordinary `./configure` recipe with no unsanctioned verb.

`source.lua` now points at the upstream release tarball. Verified on
download: 532528 bytes, matching the server `content-length`, `tar tf`
lists 169 entries.

### How the wrong upstream was found

`github.com/benhoyt/cmph` — the repo named in the brief — 404s from this
environment. Rather than record that as "repo gone" (which would have been
the same class of error the other agent in this session made), I checked
Debian's `debian/watch`, which names the true upstream:

```
version=4
opts=filenamemangle=... https://github.com/bonitao/cmph/tags ...
```

`github.com/bonitao/cmph` is reachable and is the project. Ben Hoyt is the
author; `bonitao` is the GitHub account holding the repository. The
unreachability is an egress-proxy filter, confirmed earlier by
`github.com/bminor/bash` returning the same 404 for a repository that
demonstrably exists.

Debian's own `debian/rules` never calls autoreconf either — it is plain
`dh $@` with no `override_dh_autoreconf` — which is consistent with the
upstream tarball being bootstrap-free.

## Verdict on the reviewer's rule question

The reviewer is right that the two packages could not both be right, and
right that the inconsistency was in the rulebook. **The rule is not wrong,
and cmph no longer depends on the question at all.**

AGENTS.md's build-body hygiene list (`cp`, `./configure`, `cmake`, `make`,
`make install`, `ninja`, `touch`, `find`, `mkdir`, `cat`-heredocs) is a
hard rule, and `autoreconf` is not on it. I have no authority to add a verb
to it from a package recipe, and I am not going to leave an unlisted verb
in place and call it justified.

But the premise that forced the question — "this tree's cmph has no
generated `configure`" — was an artifact of the wrong tarball. With the
real upstream release, cmph is a bog-standard generated-autotools package
that needs nothing beyond `./configure`. The rule question dissolves.

**Consistency with minizip is preserved**: if minizip genuinely cannot build
under the hygiene rule, that verdict stands on its own facts. cmph is no
longer a counterexample to it, because cmph is not the same class of
problem.

If some *future* package does ship only `configure.ac`, the honest outcome
is a WILL NOT BUILD recorded against the same rule, not a bootstrap smuggled
into a recipe.

## Options, read from `configure.ac`

- `--disable-cxxmph` — `configure.ac:38-53` hard-errors with "cxxmph
  demands a working c++0x compiler" when `AC_COMPILE_STDCXX_0X` fails. The
  C++ binding is optional and unused here.
- `--disable-benchmarks` — `configure.ac:56-62` probes for the host-only
  `hopscotch_map.h`.
- `--disable-check` — already the upstream default (`configure.ac:67-69`).
  Passed so the recipe does not lean on a default it has not verified at
  build time.

All three exist in `configure.ac`; none is guessed.

## Notes for the reviewer

- The guard is `touch aclocal.m4 configure config.h.in` then
  `find . -name 'Makefile.in' | xargs touch`. `config.h.in` is the real
  name, confirmed against `configure.ac:5` and by
  `find . -name '*.h.in'` returning exactly one file. The five subdirectory
  `Makefile.in` files are covered by the sweep.
- Every verb in the build body is on AGENTS.md's list. There is no
  `autoreconf`, no `export`, no `sed`, no patch, no `/dev/null`.
- All configure flags come from `$AUTOCONF_CONFIGURE_FLAGS`; the three
  `--disable-*` are package-local feature choices, not target facts.
- Build never fans out: `make -j1`.
