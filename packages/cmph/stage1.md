# stage1 — cmph 2.0.2 (build forecast)

## Native or target?

**Target.** cmph is a C library (`libcmph`) plus its `cmph` command-line
generator. Nothing in it invokes a compiler, intercepts a build, or needs
to run on the build host. So this package has a normal `generic.lua`.

## The build-time generator question — answered from the tree

The brief asked specifically whether cmph depends on perl or python **at
build time**, since a code generator must run on the build host. Answer:
**no perl and no python anywhere in this build.**

- `grep -rn 'perl\|python'` across `Makefile.am`, `src/Makefile.am`,
  `gendocs` and `scpscript` returns nothing.
- `src/Makefile.am:2` declares `noinst_PROGRAMS = bm_numbers` and `:36`
  builds it, but no Makefile rule invokes it, so it is built and never run.
- The bdz lookup table looks like a generated header but is **not**
  generated: `src/bdz.c:20` is a literal `const cmph_uint8
  bdz_lookup_table[] = {...}` already in the tree.
- `gendocs` and `scpscript` are `t2t`/doc helpers for the manual, not part
  of `make`.

So the only host-side requirement is the autotools bootstrap below.

## The tarball ships NO generated configure — this is the main finding

Verified against the **tarball index** (`tar tzf`), not just the extracted
directory, precisely so that absence is not read from a possibly-truncated
extraction:

```
grep -E '^cmph-2\.0\.2/(configure|aclocal\.m4|config\.h\.in|Makefile\.in)$' cmph.idx
  -> no output
grep -c 'Makefile\.in$' cmph.idx
  -> 0
```

There is **no `configure`, no `aclocal.m4`, and not a single `Makefile.in`
in the entire 717-entry archive.** `configure.ac` is present, and
`configure.ac:1` says so outright: "Process this file with autoconf to
produce a configure script."

Consequence: `./configure` does not exist until `autoreconf -fi` runs, which
executes autoconf, automake, libtool and m4 **on the build host**. Those are
therefore `@native` requires. This is the same shape as
`packages/wolfssl/` and `packages/soundtouch/`, except those two dodge it by
building with cmake; cmph has no cmake path, so the bootstrap is
unavoidable and is the only way this package can build at all.

Download verified: 3375316 bytes, matching the server `content-length`,
`tar tf` lists 717 entries.

## Build facts

| | |
|---|---|
| Build system | Autotools, **bootstrap required** (`autoreconf -fi`) |
| Generated `configure` | **ABSENT** — see above, proven from the tarball index |
| `aclocal.m4` | **ABSENT** |
| `Makefile.in` | **ABSENT** (zero occurrences tree-wide) |
| Config template | **`config.h.in`**, generated by `autoheader` during `autoreconf -fi`, from `configure.ac:5` `AC_CONFIG_HEADERS([config.h])`. It does not exist in the tarball; it appears after the bootstrap |
| Macro dir | `AC_CONFIG_MACRO_DIR([m4])` (`configure.ac:6`), shipping `acinclude.m4`, `cxx0x.m4`, `largefile.m4`, `spoon.m4` |
| Dependencies | libtool (lib_LTLIBRARIES), `libm`; `check` only for unit tests, off by default |
| C++ | optional (`cxxmph`), off in this recipe |

Because `config.h.in` is produced *by* the bootstrap, the timestamp guard
here is not tidiness — `autoreconf -fi` can otherwise re-trigger
`aclocal-1.17`/`autoheader` on tarball mtimes.

## Options, read from `configure.ac`

- `--disable-cxxmph` — `configure.ac:38-53` hard-errors with "cxxmph
  demands a working c++0x compiler" when `AC_COMPILE_STDCXX_0X` fails. The
  C++ binding is optional and unused here.
- `--disable-benchmarks` — `configure.ac:56-62` probes for the host-only
  `hopscotch_map.h`.
- `--disable-check` — already the upstream default (`configure.ac:67-69`:
  the check-based unit tests are disabled unless requested). Passed so the
  recipe does not lean on a default it has not verified at build time.

## Verdicts

| System family | Verdict | Basis |
|---|---|---|
| aarch64-android21 | WILL BUILD | `autoreconf -fi` is host-side and independent of the API level. The library itself uses no `posix_spawn`, `process_vm_readv`, `mblen`, `getpass`, `O_BINARY` or `POSIX_MADV_*`, so nothing here hits the API 21 walls. `--disable-cxxmph` removes the only hard-error path (`configure.ac:49`). |
| aarch64-android24 | WILL BUILD | Same. |
| aarch64-android35 | WILL BUILD | Same. |
| x86_64-android35 | WILL BUILD | Same. |
| x86_64-mingw | WILL BUILD | Autotools with a generated configure after the bootstrap and `--host=x86_64-w64-mingw32` from `$AUTOCONF_CONFIGURE_FLAGS`. `LT_LIB_M` (`configure.ac:32`) resolves `-lm` from the system `LDFLAGS`, which carries it on Android. |
| clang-native | WILL BUILD | `$AUTOCONF_CONFIGURE_FLAGS="--build=... --prefix=$OUT"` (`packages/clang-native/generic.lua:52`). Native, so the bootstrap is a plain host `autoreconf`. |

`armv7a-*` and `i686-*` behave like `aarch64-android*`.

The honest caveat: no row here is UNCERTAIN because the *build system* is
fully understood, but every row does depend on the bootstrap succeeding.
If `autoreconf -fi` fails on the exact automake/libtool versions in the
native prefix, all six rows fail together — that is a single shared
upfront risk, not six independent verdicts, and the builder should record
it as such.

## Note on the upstream URL

`source.lua` fetches from the Debian pool because `github.com/benhoyt/cmph`
is blocked by this environment's egress proxy: the repo, `/releases`,
`/tags`, `codeload`, and `raw.githubusercontent` all return 404, repeatedly
and with `--retry`. The same 404 comes back for `github.com/bminor/bash`,
a repository that certainly exists, so **this is a proxy filter and not
evidence that the repository is missing**. If the proxy is lifted, switch
to the upstream release tarball and re-check the version: 2.0.2 is what the
Debian pool currently ships, and I could not verify against upstream that
it is the newest release.

## Notes for the reviewer

- `autoreconf -fi` is deliberately outside the recipe-hygiene list. The
  alternative for this tree shape is not building at all, and it is
  upstream's own bootstrap. Flagging it rather than hiding it.
- The `config.h.in` in the touch list names a file that does **not** exist
  in the tarball. That is correct here and worth saying out loud: it exists
  by the time `./configure` has run, because `autoreconf -fi` generates it
  on the line above. It is not an inert guard.
- All configure flags come from `$AUTOCONF_CONFIGURE_FLAGS`; the three
  `--disable-*` are package-local feature choices, not target facts.
- Build never fans out: `make -j1`.
