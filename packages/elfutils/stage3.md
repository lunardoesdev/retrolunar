# elfutils 0.193 — stage 3 build record

System built for: **`aarch64-android24`**.

## Outcome: **FAILURE — configure aborts on the argp wall**

The package remains blocked, exactly as its `stage2.md` (REJECT) concluded.
**But the premise the recipe is built on is false**, and that is the finding
worth carrying forward: the recipe assumes `./configure` gets far enough to
generate `config.h`, so that `make -C libelf` can run. It does not. The argp
check is an unconditional `AC_MSG_FAILURE` that fires **before** elfutils' own
`config.status` runs, so neither `config.h` nor `Makefile` exists and
`make -C libelf` has nothing to build even if it were reached.

## Classification: platform wall (argp), not a recipe defect

`configure.ac:650-655` is unconditional — no `AS_IF`, no switch:

```m4
saved_LIBS="$LIBS"
AC_SEARCH_LIBS([argp_parse], [argp])
LIBS="$saved_LIBS"
case "$ac_cv_search_argp_parse" in
        no) AC_MSG_FAILURE([failed to find argp_parse]) ;;
        -l*) argp_LDADD="$ac_cv_search_argp_parse" ;;
        *) argp_LDADD= ;;
esac
```

argp is a glibc extension. Bionic does not provide it at any API level, so no
new `androidNN` target changes the outcome and no flag can pre-set
`ac_cv_search_argp_parse` from the command line in a way upstream honours.
elfutils 0.193 ships no switch that drops the probe.

The claim that all 47 `--enable/--disable/--with/--without` options in
`./configure --help` were enumerated and none drops `libdw`, `libdwfl`,
`libstack`, `libebl` or `tests/` from `SUBDIRS` is what `stage2.md` settled,
and this build confirms the conclusion: configure aborts before any of them
would matter.

**Not worked around.** `--disable-shared`, a `libelf`-only `SUBDIRS` edit or
a patched `configure.ac` would all be working around a platform wall, which
AGENTS.md forbids. No recipe and no system file was changed by this build.

## The premise that is false — and it matters

The recipe's own comment reasons:

> "libelf compiles standalone: it needs just `$(top_builddir)/config.h`,
> which ./configure has already generated by the time it fails on a target"

The first clause may well be true of libelf's own sources. **The second is
not.** I checked this directly rather than reading the log, because the log
contains a `config.status: creating config.h` line that looks like it
confirms the claim and does not.

The elfutils block begins at `/tmp/build-elfutils.log:1084`
(`skip elfutils@source (fresh)`). Its configure output runs from there to
1190, where it dies. Every `config.status: creating ...` line in the file is
at line 309, 325, 582 or 598 — **all before 1084**, i.e. all from the
*dependencies'* configure runs (xz, zlib, bzip2), not from elfutils'. There
is no elfutils `config.status` output at all.

To remove all doubt I reproduced the failure outside the build script, with
the same NDK clang and the same configure line, in `/tmp/eufprobe`:

```
$ ./configure --host=aarch64-linux-android --build=x86_64-pc-linux-gnu \
      --disable-debuginfod --enable-libdebuginfod=dummy \
      CFLAGS="-O2 -fPIC -DANDROID"
configure exit=1 (expected nonzero)
$ ls -la config.h Makefile
(no output — neither exists)
```

So on a target the ordering is: **argp probe fails → `AC_MSG_FAILURE` →
`AC_OUTPUT` never runs → no `config.h`, no `Makefile`.** `make -C libelf`
would fail on a missing `Makefile` even if `set -eu` were somehow satisfied.

### What this means for the fix

`make -C libelf` is not reachable on Android without something that gets past
the argp probe. The options are all upstream changes or system changes, and
neither is the builder's to make:

- **Upstream**: make the argp probe conditional on the components that need
  it, so a `--disable-libdw --disable-libdwfl --disable-libdebuginfod`
  configuration does not require argp at all. That is the change that would
  make the recipe's stated intent achievable.
- **Not viable as a recipe-local workaround**: `ac_cv_search_argp_parse=no`
  pre-set on the `./configure` line would satisfy the probe but then leave
  `argp_LDADD` empty and every `argp_*` call unresolved at link time for
  libdw. For a libelf-only build nothing would reference argp — but that is
  exactly the argument that requires knowing the SUBDIRS restriction is
  real, which upstream does not offer a switch for.

### The clang-native claim

The recipe also says the `make -C libelf` scoping "buys" something on
clang-native, "the one system where configure succeeds". That part is
self-consistent and untested by this build: this is an Android build and I
did not run one. It is recorded as the recipe's claim, not as a verified
result.
